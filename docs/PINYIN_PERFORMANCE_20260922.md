# 全拼性能改造（2026-09-22）

保留万象 2,202,473 词条、三阶 Beam 200 / Top50、完整 Q8 五阶重排，无 LLM。
本次不通过缩小词库、Beam 或重排候选数量提速。

## 实现

1. `Lexicon` 改为不可变紧凑 trie，分别保存排序查找边和原始插入顺序遍历边。
   原码索引采用排序后顺序构建，再恢复源次序，避免数千万次构建期散列查询。
   token JSON 流式解析，共享重复 token/字符字符串，减少逐行临时对象；加载时
   完成拼写索引，避免首次按键承担索引建立。
2. `PinyinResourceCache` 按物理文件身份、长度和修改时间引用计数共享基础词库与
   模型；全拼和小鹤的硬链接资源只加载一次。用户词、偏好及学习仍归各方案。
   用户词通过增量覆盖基础词条，不复制完整词库；有用户词时拼写索引仍会重建，
   并未实现所有索引的完全增量更新。没有磁盘缓存或空闲卸载。
3. 搜索预存模型本地整数 token，保留字符串上下文身份，避免 OOV ID 碰撞合并路径。
   复用词内分数及同上下文评分行，提前过滤已经计算过的边；使用精确最高路径
   分数跳过不能超过当前桶下界的组，等分路径仍参与竞争。浮点加法顺序保持不变。
4. 原生桥增加上下文批量评分，复用 KenLM 状态，减少反复恢复上下文和跨语言调用。
   标量 API 保留；旧 DLL 没有新入口时回退到标量路径，功能仍可用，速度收益较少。
   新版 Core 与新版 `jointkenlm.dll` 配对部署才能获得完整优化。
5. 标量缓存改为有界四路组相联缓存，避免满表清空；上下文行缓存按最近使用回收，
   每个解码器预算 32 MiB / 128 组，当前正在计算的位置允许临时超出，下次获取时
   回收。精确/通用解码器各自拥有缓存。取消仅撤回未完成的搜索状态；完整评分行
   可复用，不能把取消到一半的 Beam 当作完整增量状态。
6. Core 使用单个工作器加一个可替换待处理请求。搜索、重排、学习快照及菜单准备
   在后台完成，发布仍校验代际。普通菜单只构建一次。空格确认等待已有计算，
   等待期间释放引擎锁，不取消后重新计算。首次解码等待该方案学习日志回放，
   防止更快的资源加载抢在学习数据之前产生首选。
