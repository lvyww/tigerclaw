# Project Status (2026-03-11)

## 1. Current Active Layout

- Active runtime source is still split-process `next/`:
  - `TigerClaw.Core`
  - `TigerClaw.Overlay`
  - `TigerClaw.Dialog`
  - `TigerClaw.Shared`
- Experimental hook frontend source is available at:
  - `next/TigerClaw.Hook`
  - it is not the default TSF path and must be launched explicitly if used
- Experimental native hook frontend source is available at:
  - `next/TigerClaw.Hook.Native`
  - it is currently a C++ skeleton aligned to the existing Hook module split
  - it is not the default TSF path and must be launched explicitly if used
- TSF binary project is active at `BimeTSF2/SampleIME/` and is used by publish to build:
  - `release/x64/TigerClaw.dll`
  - `release/Win32/TigerClaw.dll`
- Reference-only upstream source trees remain under:
  - `reference/bime-master/`
  - `reference/SampleIME/`
  - `reference/weasel/`

## 3. Runtime/Feature Status

- Typing sound playback is handled by Overlay (Core only publishes sound intent/state).
- Overlay typing sound path currently uses `MediaPlayer` slots:
  - normal keys use a 4-slot player pool
  - space uses a dedicated slot
  - backspace/enter/escape/shift use a dedicated slot
  - failed slots are recreated automatically on next use
- Overlay still keeps a compatibility guard for mixed binaries:
  - if sound fields are missing in loaded `TigerClaw.Shared.dll`, the sound path is disabled instead of crashing.
- Code masking (`编码伪装`) is now applied in `TigerClaw.Core` on outward display only:
  - Core internal input buffer remains raw
  - outgoing `input_buffer` for TSF responses is masked
  - outgoing `OverlayUiState.InputCode` is masked
- Current candidate-window display behavior:
  - candidate window shows candidates/annotations only
  - code display is mainly through composition, not through the candidate window
- `TigerClaw.Hook` was reintroduced as an experimental frontend:
  - it hooks keyboard input with `WH_KEYBOARD_LL`
  - reuses the current Core named-pipe protocol
  - caret tracking was tightened to a lightweight always-on path plus on-demand precise fallback, closer to `bime-master`
  - default TSF mode remains unchanged unless `TigerClaw.Hook.exe` is launched explicitly
- `TigerClaw.Dialog` settings window was redesigned:
  - grouped form layout instead of flat card list
  - search/filter support
  - dirty-state/save-state feedback
  - `按键音量0~100` now uses a slider editor
  - empty-string config items such as `编码伪装` are now parsed and shown correctly

## 5. Known Documentation Drift

- Some docs may still claim `BimeTSF2/` was removed; that is no longer true for current publish flow.
- Current truth is: runtime logic is in `next/`, TSF packaging still uses `BimeTSF2/SampleIME`.
- Some older notes may still describe Overlay typing sound as a single 3-player reuse model; current implementation is the pooled + auto-recover variant.
- Some older notes may imply `编码伪装` only existed in config but had no effect; current implementation already affects outward display.
