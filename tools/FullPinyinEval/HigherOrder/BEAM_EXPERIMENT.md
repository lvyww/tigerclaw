# 五阶 Beam 与模型压缩实验

固定实验根：`C:/Archive/tigerclaw_sentence_ml/experiments/joint-5gram-beam-20260921/`。
所有输出与已安装输入法隔离；不修改共享 C# 解码器、生产桥或用户数据。

## 完整历史的离线适配

`prepare_beam.py` 将共享解码器和原 Joint 程序复制到实验目录，记录原件哈希，替换
KenLM 适配器为 `KenlmHistory.cs`。Previous1 保存最新字音，Previous2 在五阶时保存
之前三个字音，U+001F 分隔；三阶仍是单个 token。所有推进位置统一通过 Advance
更新，包括词条内部和锁定前缀。Beam 合并键、上下文分组和查询缓存均保留完整历史。
`beam_bridge.cpp` 接收最近到最远的历史，由 KenLM 重建原生状态；BOS 只计一次。
这是一种可验证的实验实现，字符串历史和重建状态尚未作生产性能优化。

原三元 5,246 项解码检查和 Joint 专项通过。固定 100 句 Top-50 文本、读音路径、分数
与历史结果完全一致。五阶 100 句/5,000 候选与独立逐状态 KenLM 评分误差约 5.7e-14；
983 项逐键追加/回删/重新解码 Top-50 对照通过。

## 压缩与剪枝的具体含义

原模型 ARPA 26,387,668,053 字节，原二进制 4,926,651,373 字节。
KenLM `build_binary -q 8 -b 8 -a 64 trie`：8-bit 概率、8-bit 回退权重量化，另加无损
指针压缩。量化后的完整五阶二进制 2,007,626,060 字节。量化会改变概率，需要实测。

现有文件没有原始计数，未进行计数阈值剪枝，也未将条件概率冒充频次。本实验另测
**按字音词表限制高阶上下文的剪枝**，不是标准逐条相对熵剪枝：

- 按原一元 log 概率排序，固定前 1,024 / 2,048 个字音 token；特殊边界标记始终允许。
- 所有一到三元记录保留。
- 只有历史中的全部 token 都在该集合里，才保留其四/五阶分布。
- 删除的是完整上下文的所有后继，将该上下文的回退乘数设置为 1（log=0）。
- 保留上下文集合对取后缀封闭，所以保留的高阶分布依赖的低阶概率不变，原回退权重
  仍有效。被删的分布完整回退，不需要用错误的旧回退权重给部分剩余记录评分。
- 不改目标字概率、不删词表；罕见字音仍可以通过低阶模型进入候选。

`test_context_prune.py` 用含非零回退权重的独立合成模型检查概率归一化、预期回退、
完整词表时等价及截断输入拒绝。`context_prune.cpp` 校验每阶实读记录数与 ARPA 头一致；
不能发布仅写了一部分的模型。

第一次从 Windows 挂载盘直接流式读取时提前结束，输出被下游 KenLM 拒绝，未评测。
此后增加完整记录数校验，改用逐字节复制并校验大小/SHA256 的 Linux 文件系统副本。
`context-prune-local.log` 才是最终剪枝记录，`context1024-quant.log` 是失败历史产物。
`*.failed-klm` 不能作为模型使用。

## 固定评估规则

- 原词库、字音表、完整拼音、Beam200、每字 +2、BOS/EOS 和原有同分规则均不变。
- 不使用 LLM、学习、模糊音、输入法黑盒采集；真实安装目录和模型原件保持不变。
- 原完整五阶和 q8 在同一 8,019 条测试集评估。
- 两档剪枝先在原 1,981 条 dev 上比较。预先固定“首选命中更多者胜；相同时选体积小者”，
  然后胜者跑保留的 8,019 条 test。`dev-eval.jsonl` 仅为了沿用旧入口将 split 临时标成
  test，同时保存 originalSplit=dev；不能把其准确率当作正式测试集结果。
- 额外对量化/剪枝模型重排原三元 Top-50，比较完整五阶搜索与两阶段方案。
- 全部并行解码、转换、重排结束后，固定 30 条 test，单进程依次测试各模型逐键追加/
  回删。只测离线解码器，不能声称是安装版按键延迟。
- 独立状态评分检查压缩后的新模型，不要求量化分数与原模型一致。
- 相同输入 ID/文本/编码逐条核对，首选正确要求完整消费编码。原文匹配不代表唯一合理表达。
- 训练/测试互斥、两模型训练语料一致性未独立证明。

主要驱动：`beam_run.py`、`compact_resume.py`、`compact_rescore.py`、`bench_models.py`、
`beam_report.py`。`compact_pipeline.py` 是首次中断的流程，不要用它覆盖最终产物。
原始输出、日志、候选、模型、哈希清单都在实验根，最终见该目录 REPORT.md。

## 最终结果（2026-09-22）

8,019 条：三阶 4,321；完整五阶直接搜 4,894；Q8 直接搜 4,882；开发集选中的
2048 上下文剪枝 Q8 直接搜 4,757。三阶 Top50 经完整 Q8 重排为 4,890，经剪枝 Q8
重排为 4,784。建议下一步验证未额外剪枝的 Q8 重排，未部署安装版。30 句/1,587 次
追加 P95：三阶 5.053 ms，完整五阶 69.372 ms，Q8 42.830 ms，剪枝 Q8 41.299 ms。
每句 50 候选的 Q8 预热纯评分 P95 0.313 ms。两阶段的组合按键延迟没有实测。

压缩版也通过独立 5,000 候选评分检查；剪枝版额外通过 983 项增量对照和 400 个锁定
前缀候选独立评分。bench-source/ 仅把元数据 SHA256 校验改成 8 MiB 缓冲，解码代码
与 source/ 相同，四种配置统一重测；初次计时保存在 latency-initial/。JSONL 重排
输出里的 ms=0 是兼容占位，不是计时，旁边 manifest 明确 timingMeasured=false。
