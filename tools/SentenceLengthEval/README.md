# 原虎整句按字数的 Qwen 配对评测

本工具只读日用 `release_arm64` 的虎整句码表、补充语料、白名单和模型；配置临时文件、
样本与结果写到命令行指定的仓库外目录。不得把输出目录指定为日用发布目录。
它不连接日用 Core 或 Sentence 管道，而是启动改名、字节相同的独立 ARM64 Sentence
副本，进程名和管道名都与日用版本隔离，避免日用发布脚本按进程名结束评测。

## 样本口径

`../prepare_sentence_length_eval.py` 固定随机种子 20260908，生成 2、3、4、5、6 字各
10000 条连续汉字片段。每档 webtext/news/baike/wiki 各 2500 条，目标文本全局去重，
每条原始记录每个长度最多贡献一条。前三类使用 valid 文件；wiki 使用与 KN 训练器
互补的每第 100 条记录。片段不跨非汉字字符，但不保证恰好是完整词或句。
同一短片段可能仍出现在其它训练记录里；这是记录级留出，不是短语级零重叠保证。

编码使用现有 `encode_shortest_text`：逐字选整句可用的最短优先码，需要时附加选重符。
不按能否进入候选池或能否识别正确筛样本。每组按目标文字字数分档，不按输入码数或
识别结果字数分档。

## 运行

先用 Python 生成仓库外的 `cases.json`，再构建本目录 csproj。程序参数依次为：

```text
TigerClaw.Core.Tests.dll REPO_ROOT OUTPUT_DIRECTORY WORKER_ID WORKER_COUNT [MAX_NEW_CASES]
```

Windows 下以 dotnet 执行，并传 Windows 绝对路径。例如在两个独立终端分别运行 worker
`0 2` 与 `1 2`，可避免 CPU 并发无限膨胀。各进程复用 n-gram 实例及一个原生 Qwen
scorer（scorer 自身也使用多线程）。运行期间不要重新构建该评测输出。

每条完成即追加 `rows-N.jsonl`，重新运行相同参数会跳过已有 ID。输出目录出现 `STOP`
文件后，各进程完成当前样本再退出。续跑必须保持样本、模型、码表、规则和 worker 数
不变；不同实验使用不同输出目录。意外中断后若最后一行 JSON 不完整，应先归档并修复
该行，不要混入已完成结果。

## 排序与统计

直接调用生产 Core 的普通 SentenceInputDecoder 及 InputMethodEngine 的 Qwen 合并函数。
Beam 2000，候选 20，重排前 5，字符奖励 2.0，最优码单字奖励 5.0；高频限制 1500，
允许单字重码组句。禁用提前上屏，逐条清空上下文。
2026-09-08 原始基准权重：基准首选最多 2 字时 0.30，其余 0.84；后续运行以当时生产
代码、manifest 中的 Core 指纹和每条记录的 weight 为准。比较的是同一批样本的
最终首选完全匹配率；单一候选或空候选跳过无意义的 Qwen 调用，但仍计入分母。
模型错误会终止 worker，不会用回退结果冒充开启 Qwen 的结果。

`../summarize_sentence_length_eval.py OUTPUT_DIRECTORY --complete --write` 验证每档
10000 条、ID 无重复，生成 `summary.json` 与 `summary.csv`，包括 Top-1、MRR、Top-5/20
入池率、纠正/退化计数、配对准确率差的近似 95% 区间及示例。
不带 `--complete` 可查看中间进度，不能把中间结果称为完整评测。
每个 worker 的 manifest 保存实际模型、scorer、Core、样本与码表的大小及 SHA-256。

这是原虎整句的离线、无上下文、最优码输入基准，不应直接外推到字词整句模式、非最优
码输入、上下文连续输入或真实按键延迟。

## 2026-09-08 第一轮权重校准（已被下一节替代）

运行 `python3 tools/tune_sentence_qwen.py OUTPUT_DIRECTORY`（需要 NumPy）。
先用原始权重复现全部 50000 条生产首选，再按 source + record 的 SHA256 分组，
34683 条用于调参、15317 条留作验证，同一记录不会跨集合。调参集内部再按记录做
5 折交叉验证，比较统一权重、基准首选字数分档、等长/异长两档、字数与异长组合。
权重网格 0..1.20，步长 0.05；训练正确数并列取较低权重，交叉验证并列取参数更少的
方案。不是按正确答案字数选权重。只有基准首选 2..6 字参与新参数，范围外沿用旧值。

5 折总正确数依次为 34387、34397、34390、34387，选中字数分档，在整个调参集拟合
得到 2/3/4/5/6 字权重 0.10/0.35/0.45/0.25/0.55。同一码的所有候选共用该权重，
不对负的 Qwen 总分使用候选各自的权重，避免引入依赖分数绝对零点的长短偏置。
另外探索了 `QwenScore + c * (候选字数 - 基准首选字数)`，c 从 0 到 16、步长 0.5，
调参集最优 c=0，不加入额外字数补偿。探索结果不意味着其它归一化方案均无效。

验证集旧/新正确数 15157/15164（98.9554%/99.0011%），纠正 44、改错 37；配对差
近似 95% 区间为 -0.0695..+0.1609 个百分点，尚不能证明稳定收益。异长集合
7687 条，旧/新正确数 7580/7578，纠正 28、改错 30；等长集合 7630 条，7577/7586。
整体 50000 条旧/新为 49514/49573，但包含调参集，不能作为独立泛化收益。
按目标字数的全量新准确率为 98.17%、99.12%、99.42%、99.52%、99.50%；两字目标
相比旧策略下降，不能宣称每档改善。当前只是有限基准下的校准，需继续真实输入验证。
验证集在探索阶段曾输出摘要；最终家族/参数仅由调参集内部交叉验证选择，仍建议用
未查看过的新语料做下一轮独立确认，不把本次验证集重复作为调参目标。

输出 `calibration.json` 和 `calibration-predictions.json`。构建后用原运行命令追加
`--replay`（替代 MAX_NEW_CASES），分别跑 worker 0 和 1：重做实际 Core n-gram
解码并逐项核对候选文字、原始分数、码表 rank，再将缓存 Qwen 分数传给实际
ApplySentenceNeuralScores，核对全部首选与离线预测一致。此模式不启动 Qwen，
不覆写原始 rows/manifest；验证结果写入 calibration-replay-N.json。

## 第二轮：候选自身字数，总权重固定为 1（当前源码）

`python3 tools/compare_sentence_qwen_convex.py OUTPUT_DIRECTORY` 读取原始缓存，保留
相同的记录分组和内层 5 折，比较三种策略：第一轮整组共用权重、原始分数凸组合、
每个输入的有效前五候选内分别做 n-gram/Qwen 均值方差标准化再凸组合。标准化只依赖
当前候选、不使用答案；标准差不足 1e-9 时输出零。后两种按候选自身字数设 alpha，
公式 `(1-alpha)*N + alpha*Q`，alpha 搜索 0..1、步长 0.05，6 起点坐标搜索、至多
6 轮，不宣称穷举全局最优。并列优先较小参数，家族按调参集内部 CV 总正确数选定。

三种 CV 正确数依次为 34397、34400、34343，选中原始分数凸组合；全调参集得到
候选 2 字 alpha=0.15，3..6 字 alpha=0.30。1 字候选仍用原 lambda=0.30 换算的
alpha，超过 6 字候选用原 lambda=0.84 换算；它们与其它候选竞争时也保持总权重为 1。
如果 n-gram 基准首选自身不在 2..6 字内，则整组保持原加法策略，不外推短文本校准。
这不是把上一轮 lambda 直接当作 alpha，也不是依据答案字数选择权重。

相对第一轮策略，验证集 15317 条正确数 15164 -> 15179（纠正 29、改错 14）；
异长 7687 条为 7578 -> 7594（纠正 27、改错 11）；等长为 7586 -> 7585。
标准化方案正确数 15147，未采用。原始凸组合全量 50000 条正确数为 49586，
按目标 2/3/4/5/6 字分别 9849/9888/9948/9947/9954；上一轮分别
9817/9912/9942/9952/9950，故三字目标明确有退化，不能称为全字数提升。
内部 CV 仅多对 3 条；验证集已被多轮探索查看，近似区间未校正重复比较，
必须用新的未查看语料确认，不可当作独立、确定的泛化提升。

结果及参数写入 `convex-comparison.json`、`convex-predictions.json`。实际 Core 回放
命令在原 worker 参数后追加 `--replay convex`，校验文件为 `convex-replay-N.json`。
第一轮 calibration-* 文件保留为历史对照，不能用当前生产策略回放第一轮预测。
未来重新运行带 Qwen 的评测时，每行含 `scoring_policy=candidate-convex-v1`；
凸组合行的 `alphas` 依照原始前五候选顺序保存，`weight=0`，范围外加法策略才记录
非零 `weight`。两个离线调参脚本只接受此次原始加法基准，拒绝混入新版数据。

## 冻结参数的新语料确认

生成器支持 `--exclude-cases PREVIOUS_CASES --seed 20260909`：每种来源只读取前批
最大记录编号之后的记录，同时排除前批所有目标文本，仍保留原训练器的记录级留出
规则。`cases-sampling.json` 保存截断位置、随机种子及输入/输出指纹。首次生成后
冻结四个策略，不再根据确认集调参：关闭 Qwen、最初加法参数、第一轮整组参数、
当前凸组合。运行方式与上文相同，各长度仍为 10000 条。

当前评测器每次只调用一次 scorer，使用实际 Core 比较器另外记录 `legacy_top`、
`shared_top`、`prefer_score`，与当前策略配对比较。续跑拒绝不同评分策略，以及
不同 worker 数、模型、Core、码表、白名单和样本指纹，防止拼接不同实验。

`python3 tools/summarize_sentence_qwen_confirmation.py OUTPUT_DIRECTORY --complete --write`
核对每档数量、跨批原始记录和目标文本不重叠及当前模型指纹，生成
`confirmation-summary.json/csv`。同一原始记录可贡献不同长度片段，配对区间因此
采用按 source+record 聚类的标准误，不把这些片段误当独立样本；子组区间未做
多重比较校正。不加 `--complete` 仅用于进度，不可称为最终确认结果。
